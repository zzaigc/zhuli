# 13-混沌测试（v0.3.0，测试专用）

## 一句话：混沌是什么，不是什么

混沌工程是**故障注入的弹性测试**：在受控环境里故意制造故障，
看系统能不能恢复，再根据结果调参数。它比压力测试更广：
压力测试是“压得多”（并发、数据量往上加，看性能极限），
混沌是“坏得巧”（服务挂了、网络断了、模型报错、页面崩了，
看恢复能力）。混沌本身不会自动让系统变稳定，真正让系统变稳
的是后面那步：修掉找到的问题、调好参数、再反复测。

## 它注入什么

模块在 `src/zhuli/chaos/`，只用标准库和已有依赖，每种故障都
具名、显式、记日志，注入后以异常结束，绝不返回假成功：

| 故障 | 模拟场景 | 期望恢复（现有机制） |
|---|---|---|
| llm_401 | 模型调用 401（无有效密钥） | 升级处理，不重试 |
| llm_429 | 模型调用 429（限流） | 重试 |
| llm_timeout | 模型调用超时 | 重试 |
| browser_page_crash | 浏览器页面崩溃 | 重规划 |
| browser_element_missing | 页面元素不存在 | 重规划 |
| browser_nav_timeout | 页面跳转超时 | 重试 |
| provider_network_delay | 供应商网络延迟（模拟，不发真实请求） | 重试 |
| provider_network_loss | 供应商网络中断（模拟） | 降级（蜂巢降级回单脑等） |
| tool_slow | 工具调用变慢（模拟延迟） | 重试 |
| tool_failure | 工具调用失败 | 降级 |
| service_restart_mid_task | 任务中途服务重启（模拟中断标记） | 从快照回滚恢复 |

它练的是 orchestrator 已有的机制：失败重试、快照回滚、
连续 3 次相同动作判定循环、重规划上限 3 次、批评与风险、
蜂巢失败降级回单脑、浏览器不可用时优雅降级。
**没有为混沌削弱任何护栏、批准或安全检查。**

## 它校准什么（只建议，不自动改配置）

一次运行结束后，报告会给出参数范围建议，运营者人工决定
是否采纳，模块**绝不改写 `config/settings.yaml`**：

- 可重试故障重试用尽：先看超时（120 秒起步，150~300 秒区间
  人工试）和重试次数（2~3 次），不要无限重试。
- 频繁重规划：重规划上限保持 3 次，优先修规划与页面选择器，
  而不是直接放宽上限。
- 频繁降级：保持蜂巢默认关闭；手动规模无上限，自动模式 2~8；降级成功是正常兜底，
  应查供应商稳定性，而不是调大蜂群。
- 未恢复的故障：先修根因，循环阈值保持 3 次，升级处理保持
  人工确认；**不能靠调阈值把失败记为成功。**
- 全部恢复：保持现有参数不变。

## 安全规则（代码强制）

1. **默认关闭**：配置 `chaos.enabled` 默认 False，运行时默认也关闭。
2. **显式开启才生效**：CLI 必须带 `--chaos-test`；控制台接口
   开启还必须带测试专用确认串；普通任务消息里带 chaos 字段
   也不会开启（WebSocket 任务分发从不解析 chaos 字段）。
3. **只在隔离目录跑**：快照与报告目录必须在系统临时目录下；
   拒绝项目根、项目 `.zhuli_runtime`、用户主目录等真实路径。
   快照只复制、不删除，恢复只覆盖测试副本里的同名文件。
4. **不碰真实数据**：不删除真实运行时数据，不对作者 main 分支
   做任何事，不调用真实模型、浏览器或网络来“制造”故障。
5. **正常控制台没有混沌按钮**：混沌开关是有意的接口级测试
   开关，不是给日常用户点的功能；测试结束后重启即关闭。

## 怎么用（只在测试副本上）

```bash
# 示例：临时目录里跑 4 个故障并输出报告，不启动服务、不改配置
PYTHONPATH=src python -m zhuli.main --chaos-test --chaos-sample
# 报告在系统临时目录下的 zhuli-chaos-sample-*/chaos-report.md

# 服务里的测试接口（测试专用，重启后关闭）
curl http://127.0.0.1:8000/api/chaos
# 开启需 POST {"test_mode": true, "confirm": "CHAOS-TEST-ONLY"}
# 关闭：POST {"test_mode": false}
```

## 它不做什么

- 不是压力测试工具，不测吞吐与延迟极限。
- 不是自动调参器，不改写任何配置文件。
- 不是生产功能：不能在正常用户任务里开启，不能用来“压”
  真实服务、真实浏览器配置或真实数据。
- 不声称已验证真实模型、真实浏览器端到端：本版混沌测试
  用的都是桩步骤与模拟故障，真实链路仍需真实密钥与 Chromium。

## 测试

`tests/test_chaos.py`（标准库 unittest）：默认关闭、显式开启、
隔离目录拒绝、每种注入器触发期望恢复、重试用尽记失败、
快照恢复、校准建议不写配置、普通任务消息不能开启。
