# 07 · 安全与军事级加密

## 加密规格

| 层面 | 算法 | 参数 |
|---|---|---|
| 对称加密 | **AES-256-GCM**（AEAD） | 256 位密钥、96 位随机 nonce、128 位认证标签 |
| 密钥派生 | **PBKDF2-HMAC-SHA256** | 600,000 次迭代、32 字节随机盐 |
| 密文绑定 | **AAD**（附加认证数据） | 绑定账户名，防密文跨账户搬运 |
| 秘密比较 | **常数时间比较** | `hmac.compare_digest`，抗时序侧信道 |
| 完整性 | GCM 认证标签 | 密文被篡改 → 解密直接失败 |

> AES-256-GCM 是 AEAD 密码：同时提供**机密性 + 完整性 + 抗篡改**，
> 被 TLS 1.3、IPsec、Signal 等采用，属于现代密码工程的标准选择。

## 信封格式

```
ZH1.<base64(nonce(12) || ciphertext || tag(16))>
```

- 每条记录使用**独立随机 nonce**，杜绝 nonce 复用风险；
- `ZH1.` 前缀用于识别「已加密」，兼容历史明文记录（自动按明文读取）。

## 模块分工

| 模块 | 职责 |
|---|---|
| `security/crypto.py` | 原语：KDF、seal/unseal、轮换、常数时间比较、擦除、指纹 |
| `security/secure_string.py` | `SecureString`：内存中仅以密文持有敏感文本 |
| `security/vault.py` | `SecurityVault`：keyring + 信封加密的双层保险库 |
| `credential/vault.py` | 对外 API（save/get/delete），底层委托 SecurityVault |

## 双层防护：为什么 keyring 之上还要加密

- keyring 的部分后端本质是文件型明文/弱保护存储；
- 凭据若被同步、备份或迁移，信封层仍然保护它；
- AAD 绑定账户名，杜绝「把 A 账户密文搬到 B 账户」的替换攻击。

## SecureString（内存中密文持有）

```python
sec = SecureString("myPassword", label="cred:password")
sec.reveal()   # 仅在注入瞬间解密
repr(sec)      # "<SecureString ***>"（绝不泄露）
sec.wipe()     # 主动销毁，之后 reveal 会报错
```

用途：凭据卡片回传的密码/API Key 在内存中只以密文存在，
即使进程被内存转储也拿不到可直接使用的明文。

## 主密钥管理

优先级：

1. **环境变量 `ZHULI_MASTER_KEY`**（推荐，口令不落 OS 凭据库）
2. **系统凭据库**（开箱即用：首次自动生成随机口令并保存）
3. **仅内存会话密钥**（keyring 不可用时；重启后旧密文不可解 —— 安全默认）

支持**密钥轮换**：`rotate(envelope, old_key, new_key)` 无需把明文暴露到磁盘。

## 安全默认行为

- 明文**绝不**写入配置文件或日志；
- 单次任务填卡的值默认只存内存，进程退出即清除；
- 注入完成后立即 `wipe()`；
- 日志对敏感值统一脱敏为 `***`；
- 缺 `cryptography` 依赖时**优雅降级**为「仅 keyring 保护」并告警，绝不崩溃。

## 其它安全机制（非加密但同属安全模型）

| 机制 | 说明 |
|---|---|
| 命令注入防护 | 一律 `subprocess` 参数列表，禁止 shell 字符串拼接 |
| 危险命令护栏 | `computer/guard.py` 分级：allow / confirm / deny |
| 敏感操作护栏 | `browser/guard.py` 识别提交/支付/删除/跨域 |
| 风险智能体 | 与规则护栏**互补**的 LLM 风险分级（safe/confirm/danger） |
| 凭据隔离 | LLM 只收到「需凭据」信号，绝不接触明文 |
| 人在回路 | 危险操作/命令弹确认，可暂停/接管/停止 |

## 自查接口

```
GET /api/security
→ {"crypto_available": true, "encryption_enabled": true,
   "cipher": "AES-256-GCM", "kdf": "PBKDF2-HMAC-SHA256 x600000",
   "key_fingerprint": "0b0dd3f2...", "master_source": "keyring"}
```

只返回**指纹与来源**，不含任何秘密，可安全展示在控制台。

## 运维建议

1. **设置 `ZHULI_MASTER_KEY`**（口令不落 OS 凭据库）；
2. 定期轮换主密钥（用 `rotate()`）；
3. 备份 `.zhuli_runtime/` 时注意其中含加密库与 profile；
4. 不要在配置中写任何明文秘密。
