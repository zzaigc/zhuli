# 04 · 多智能体与蜂巢思维

## 两种协作形态

| 形态 | 入口 | 特点 |
|---|---|---|
| **流水线多智能体** | `Coordinator` | 串行审批：actor 提议 → critic + risk **并行**审查 → 执行 |
| **蜂巢共识** | `HiveCoordinator` | N 个执行体并行提案 → 评审者并行投票 → 共识择优 |

两者由 `build_coordinator()` 按 `policy.hive_mode` 自动选择，对上层 `Orchestrator` 接口完全一致。

## 智能体团队

| 智能体 | 职责 | 输出 | 可绑 capability |
|---|---|---|---|
| `planner` | 目标拆解 + 重规划 | subtasks / verification / tools | reasoning |
| `observer` | 观察蒸馏（剔除无关元素） | summary / relevant_ids / obstacles / progress | default |
| `actor` | 提出下一步动作（蜂巢时为 `actor#1..#4`） | Action（含 thought / expected_effect） | reasoning |
| `critic` | 执行前审查 + 执行后反思 | verdict ∈ {accept, revise, abort} | reasoning |
| `risk` | 风险分级 | level ∈ {safe, confirm, danger} | default |
| `skill_miner` | 技能提炼与迭代 | name / trigger / procedure / tags | reasoning |
| `tool:*` | 外部工具（CodeBuddy/Trae/OpenCode） | 任务结果文本 | — |
| `skill:*` | 由技能升格的专项经验 | 经验上下文 | — |

## 蜂巢思维（分布式群体决策）

### 流程

```
        ┌─ actor#1（temperature 0.2 · 保守）─┐
观察 → 黑板 ─┼─ actor#2（temperature 0.5 · 均衡）─┼─→ 并行提案
        └─ actor#3（temperature 0.9 · 探索）─┘
                     │
        （每个提案同时送审：全部并发）
        ┌────────────┴────────────┐
     critic（加权）            risk（加权）      → 并行评审
        └────────────┬────────────┘
                 共识（按分数择优）
                     │
        选中动作执行 / 最优仍被否决 → 重规划
```

### 加权投票规则

| 来源 | 取值 | 分值 |
|---|---|---|
| critic | accept / revise / abort | +2 / +1 / −2 |
| risk | safe / confirm / danger | +2 / 0 / −2 |

总分最高者胜出；若**最优提案仍被判 `abort` 或 `danger`**，则整步否决并触发重规划。

### 四大蜂巢特性

1. **群体多样性**：多个执行体用不同 temperature（也可配不同 provider），避免单一思路陷入局部最优。
2. **全并发**：提案与评审全部并发，增加成员**不线性增加耗时**（实测 3 体 0.31s vs 串行 0.90s）。
3. **容错**：个别成员 LLM 报错时不参与投票，其余照常；**全部失效则自动降级**为单体决策。
4. **共享黑板**：所有认知（页面状态、提案、投票、决策）写在 `Blackboard` 上，可观测、可复盘。

### 黑板（Blackboard）

```python
bb.write("ctx", "subtask", subtask)          # 共享上下文
bb.write("actor#1", "proposal", "click")     # 各执行体提案
bb.write("actor#1", "vote", 4)               # 投票得分
bb.write("hive", "decision", "scroll")       # 最终共识
```

每步开始 `reset()` 避免跨步污染；`snapshot()` 供事件/日志导出。

## 自进化：技能 → 专项智能体

```
成功任务 → skill_miner 提炼 → 存入 SQLite
                                  │
新任务 → 检索（语义 embedding / 关键词回退）→ 注入经验上下文
                                  │
技能成功复用 ≥ policy.skill_promote_threshold
                                  │
                       自动升格 → 注册为 skill:* 专项智能体
                                  │
                    团队模块数 +1（越用越多、越用越聪明）
```

技能再次被使用时，会把新经验**合并精炼**进既有技能（`🔄 迭代更新技能`），让技能越用越准。

## 配置

```yaml
policy:
  multi_agent: true        # 总开关（false = 单脑模式）
  self_critique: true      # 执行前批评
  observer_enabled: true   # 观察蒸馏
  skill_promote_threshold: 2
  hive_mode: false         # 蜂巢共识（更准，但 token 消耗更高）
  hive_size: 3             # 蜂群规模 1~4

agents:                    # 每个角色可绑不同 provider/capability
  planner:     { provider: deepseek, capability: reasoning }
  critic:      { provider: openai,   capability: reasoning }
```

> 蜂巢模式默认关闭：它在关键决策上更强，但每步 token 消耗约为流水线的 3 倍。

## 实测结论（免联网 · 假智能体）

| 验证项 | 结果 |
|---|---|
| 共识择优 | 三提案 click(0) / type(1) / scroll(4) → 选中 **scroll** |
| 并发 | 3 体各 0.3s → 总 **0.31s**（串行 0.90s） |
| 容错 | 1 体失效 → 2 个有效提案，仍正常共识 |
| 降级 | 全体失效 → 自动回落单体决策 |
| 黑板 | subtask / proposal / vote / decision 均正确写入 |
