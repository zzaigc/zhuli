1. 先读 **[01-产品与架构总览](01-产品与架构总览.md)**：知道这个系统是什么、为什么这样设计。
2. 再读 **[02-目录结构与模块职责](02-目录结构与模块职责.md)**：知道代码在哪、谁负责什么。
3. 然后读 **[03-决策链](03-决策链.md)** 与 **[04-多智能体与蜂巢思维](04-多智能体与蜂巢思维.md)**：这是本项目的灵魂。
4. 动手前必读 **[05-事件契约](05-事件契约.md)**（前后端唯一耦合点）与 **[08-二次开发指引](08-二次开发指引.md)**。
5. 改提示词请看 **[prompts/](prompts/)**；改安全相关请看 **[07-安全与军事级加密](07-安全与军事级加密.md)**。

## 这个项目的一句话概括

**ZHULI = 本地运行的多智能体蜂巢决策系统**：用一支可跑在不同模型上的智能体团队（规划/观察/执行/批评/风险/技能挖掘），
通过「共享黑板 + 群体并行提案 + 投票共识」完成浏览器自动化、本地命令、视频剪辑与外部 AI 工具对接，
并把每次成功经验沉淀进 SQLite，随使用自动升格为新的专项智能体——**越用越多模块、越用越聪明**。
所有敏感数据以 AES-256-GCM 军事级加密保护。

## 关键不变式（改动时不得破坏）

> 这些是系统的「宪法」，任何重构都必须保持成立，否则会引发连锁问题。

1. **能力模块对 `core.orchestrator` 暴露统一接口**：browser / computer / video / integrations 的可替换性。
2. **连接器只依赖 browser / computer 的公开接口**，不得绕过它们直接操作内部实现。
3. **命令执行一律用 `subprocess` 参数列表**，禁止 shell 字符串拼接（防注入）。
4. **凭据明文绝不进入 LLM、日志与配置文件**；内存中用 `SecureString` 密文持有。
5. **前后端只通过 `Event` 联合类型耦合**；新增事件必须同时更新 `events.py` 与前端分发。
6. **智能体行为由 `prompts/` 单独定义**，改行为优先改提示词，而非硬编码进逻辑。
7. **所有运行时产物落在项目内 `.zhuli_runtime/`**，绝不写入 C 盘。
8. **决策链必须可观测**：规划结论、思维链、智能体活动、反思结论都要推到控制台。
