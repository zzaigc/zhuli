# 05 · 风险智能体（risk）

**源码**：`src/zhuli/agents/prompts.py` → `RISK_AGENT_PROMPT` / `RISK_SCHEMA`
**职责**：给待执行动作做敏感度/风险分级，与**规则护栏互为补充**。

## 提示词

```
你是「风险智能体」。评估一个待执行动作的敏感度与风险等级，与规则护栏互为补充。

level 取值：
- safe: 可直接执行
- confirm: 需用户确认（提交表单、删除、跨域跳转、敏感命令等）
- danger: 高危，需明确确认并尽量换更稳妥方式（支付、格式化、不可逆删除等）

只输出结构化字段，不要解释。
```

## 输出 Schema

```json
{
  "type": "object",
  "properties": {
    "level":    { "type": "string", "enum": ["safe", "confirm", "danger"] },
    "category": { "type": "string" },
    "reason":   { "type": "string" }
  },
  "required": ["level"]
}
```

## 与规则护栏的分工

| 机制 | 类型 | 优点 |
|---|---|---|
| `browser/guard.py`、`computer/guard.py` | **规则**（确定性） | 稳定、可预测、不依赖模型 |
| `risk` 智能体 | **模型判断**（语义） | 能识别规则未覆盖的新型/组合风险 |

两者互补：规则护栏保证底线，风险智能体补语义盲区。

## 系统行为

| level | 行为 |
|---|---|
| `safe` | 直接执行，不打扰用户 |
| `confirm` | 弹人在回路确认；用户取消则记「用户取消了高风险操作」并继续 |
| `danger` | 弹确认（蜂巢模式下直接**否决**该提案，换其它候选） |

## 避免重复弹窗

规则护栏与风险智能体可能同时判定需确认。系统用 `_pre_confirmed` 标记去重：
风险智能体已确认过的动作，规则护栏不再二次弹窗。

## 在蜂巢中的投票权重

```python
_RISK_SCORE = {"safe": +2, "confirm": 0, "danger": -2}
```

这让蜂巢在多个候选动作中**天然偏好更安全的那个**——即使某个动作能达成目标，
只要风险高就会在投票中落选。这是蜂巢提升安全性的关键设计。
