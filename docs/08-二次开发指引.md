# 08 · 二次开发指引（扩展的标准姿势）

## 一、新增一个智能体

1. 在 `src/zhuli/agents/prompts.py` 中定义它的**提示词与输出 Schema**：

```python
NEW_AGENT_PROMPT = """你是「某某智能体」。职责：……
只输出结构化字段，不要解释。"""

NEW_SCHEMA = {
    "type": "object",
    "properties": {"result": {"type": "string"}},
    "required": ["result"],
}
```

2. 在 `agents/roles.py` 中实现角色：

```python
class NewAgent(StructuredAgent):
    def __init__(self, capability="reasoning", provider=None):
        super().__init__("new_agent", NEW_AGENT_PROMPT, NEW_SCHEMA, "emit_new",
                         capability=capability, provider=provider,
                         description="一句话职责")

    async def run(self, some_input: str) -> dict:
        return await self._call(f"输入：{some_input}")
```

3. 在 `agents/__init__.py` 的 `_DEFAULT_AGENTS` 中登记，即可被自动构建：

```python
_DEFAULT_AGENTS["new_agent"] = ("default", NewAgent)
```

4. 在 `Coordinator` 中编排它的调用时机（用 `self._get("new_agent", NewAgent)` 取用）。

> 提示词与 Schema 分离在 `prompts.py`，是为了让「改行为」不必动逻辑代码。

## 二、新增一种能力（如 PDF 处理）

1. 建目录 `src/zhuli/pdf/`，实现统一接口：

```python
async def execute(action, ctx) -> dict: ...
async def observe(ctx) -> dict: ...
```

2. 在 `core/orchestrator._execute()` 的路由中加分支；
3. 在 `llm/prompts.py` 的 `ACTION_SCHEMA` 枚举中加入新动作名；
4. 在 `prompts/03-actor.md`（及 `agents/prompts.py`）中说明该动作，让模型知道何时用它。

## 三、新增一个外部工具连接器

1. 在 `integrations/` 中实现 `BaseConnector` 子类：

```python
class SomeToolConnector(BaseConnector):
    name = "sometool"
    kind = "browser"   # 或 "computer"

    async def run(self, task, *, page=None, on_output=None) -> str:
        # 复用 browser / computer 的公开接口，不要绕过它们
        ...
```

2. 在 `orchestrator._CONNECTOR_REGISTRY` 中注册；
3. 在 `config/settings.yaml` 的 `integrations` 段加入配置。

它会自动被包装成 `tool:*` 智能体，可直接被派发任务。

## 四、修改提示词

- 各智能体提示词集中在 **`src/zhuli/agents/prompts.py`**；
- 规划/反思/技能沿用 **`src/zhuli/llm/prompts.py`**；
- 本文档的 **`docs/prompts/`** 是它们的**可读副本**，改代码后请同步更新文档副本。

## 五、常见改动位置速查

| 想改什么 | 改哪里 |
|---|---|
| 智能体说什么话/输什么结构 | `agents/prompts.py` |
| 智能体之间怎么协作 | `agents/coordinator.py` / `agents/hive.py` |
| 蜂巢投票权重 | `agents/hive.py` 的 `_CRITIC_SCORE` / `_RISK_SCORE` |
| 循环检测阈值 | `orchestrator._detect_loop(threshold=3)` |
| 重规划上限 | `orchestrator._do_replan` 中的 `replan_count > 3` |
| 技能升格阈值 | 配置 `policy.skill_promote_threshold` |
| 加密强度 | 配置 `security.pbkdf2_iterations` |
| 事件类型 | `core/events.py` + 前端分发（**必须同步**） |

## 六、开发纪律（防回归）

1. **不动不变式**：见 [README 的关键不变式](README.md#关键不变式改动时不得破坏)。
2. **加事件必同步前端**，否则前端收到未知事件。
3. **命令一律参数列表**，禁止 shell 拼接。
4. **敏感值先脱敏再入日志**；凭据用 `SecureString`。
5. **新逻辑要可观测**：能推事件就推事件，否则控制台看不到。
6. **容器化路径**：任何运行时产物路径都要落在 `.zhuli_runtime/`。

## 七、调试技巧

- 无 API Key 时可用「假智能体」替换注册表中的角色（实现同名 `run()` 即可），
  这是本项目验证并发/共识/容错的标准手法，无需联网。
- 服务启动期错误也能看到：WebSocket 会回放最近 100 条历史事件。
- 控制台「🤖 智能体」可查看团队规模与协作模式；「🧠 技能库」可查看/编辑/删除技能。
